# Simple_tokio_app — приём и разбор данных реографа РКМ / РКМ-С

GUI-приложение (egui) для чтения потока с COM-порта, синхронизации 20-байтных кадров,
декодирования 5 каналов (РЕО-1, BASE-1, ЭКГ, BASE-2, РЕО-2) и отображения/записи CSV.

## Протокол

- Кадр: **10 слотов × 2 байта = 20 байт**, частота **200 Гц**.
- Значимые биты данных: `6..1` (маска `0x7E`). Бит 0 — служебный (синхронизация).
- Синхронизация: три подряд байта с `bit0 == 0`; **второй** — начало кадра (старший байт РЕО-1).
- Декодирование: `to_int` / `to_signed_int` / `convert` (биполярные РЕО/ЭКГ — знаковые с инверсией).
- **РКМ** и **РКМ-С** дают один и тот же `Frame`; у РКМ-С бит 7 всегда 0 (на decode не влияет).
- Неиспользуемые слоты (3, 6, 7, 9, 10) в модель не попадают.

## Фильтры данных (RCM / RCMS)

После декода кадра данные проходят цепочку как в JavaFX-референсе:

- **RcmIn** — 10 каналов (`RcmConverter`), signed expand для RHEO/ECG  
- **RcmOut** — µΩ / mΩ / Ω / mV + `smoothingImpulsive(4)`, FIR BASE (BR_F200/025/005)  
- **RCMS** — pass-through поверх RcmOut (`QS_2` ← `QS_1`)  
- **Calibration** — RRS / peak-to-peak по RHEO/BASE/QS  

Ресурсы: `tokio_app/resources/rcm/` (`rcm.json`, `BR_F*.txt`).  
В UI: выбор профиля + чекбокс «Фильтры».

## COM-порт (по умолчанию)

`38400, 8N1, RTS=true, DTR=false` — по документации базового РКМ; для РКМ-С отдельной
спецификации нет, те же значения как рабочее предположение (`SerialConfig`).

При запуске и по кнопке **Автопоиск** приложение само перебирает COM-порты (~400 мс каждый),
ищет поток с ≥5 валидными кадрами РКМ/РКМ-С без потери синхронизации и подключается к найденному.

## Структура `com_port`

| Модуль | Назначение |
|--------|------------|
| `serial.rs` | Открытие порта |
| `sync.rs` | `FrameSynchronizer` |
| `decode.rs` | Чистый decode |
| `model.rs` | `Frame` |
| `reader.rs` | Связка порт → sync → decode |


- `1_SerialService_2018-Oct-24_19-29-28_rcm.bin`
- `2025-12-08_19-07-29_029_rcms.bin`

Без файлов fixture-тесты аккуратно пропускаются; синтетические тесты всегда выполняются.
